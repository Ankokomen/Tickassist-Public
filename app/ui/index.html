Google Sheets Lookups

Add as many sheets as you like. Each one is looked up by a field in the Note Generator (Imaging Package, Serial Number, Device Type, ...): type that value and TickAssist fills the other fields from the matching row. Share each sheet as “Anyone with the link can view” (or File → Share → Publish to web). TickAssist only reads them.

Columns whose header already reads like a field (OS, Romexis Ver, DIDAPI, Device Firmware, Reco Unit, ...) map by themselves; list only the ones that don't in a sheet's mapping. Fields: imaging_package, os_version, device_type, serial_number, device_firmware, device_tool_version, didapi, romexis, reco_os, reco_pc, reco_firmware, part_rec, error_info, dealer_name, contact, contact_type, problem, next_steps, outcome.

Tech roster (adds new callers)

A sheet with Tech Name in column A, Phone in column B and Dealer in column C. When a ticket is saved, TickAssist looks for that Contact Name + Phone and, if the pair isn't there, adds it to the next empty row. A shared link can only be read, so a small Google script in the sheet does the writing: press “Show the script” and follow the steps. Nothing is sent until both boxes below are filled in; after that each saved ticket's contact name, phone and dealer go to that sheet.

Anyone who has the address and this key can add rows to the roster, so treat it like a password.
A number that is already in the roster under another name always asks first, and shows whose it is. Every row TickAssist adds is listed in the sheet's “TickAssist log” tab.
  1. Open the roster sheet, then Extensions → Apps Script.
  2. Delete what is there and paste the script below. Change the KEY line to a long random secret (and the TAB / HEADER_ROWS lines if your sheet differs).
  3. Deploy → New deployment → Web app. Execute as Me, who has access Anyone. Allow when asked.
  4. Copy the Web app address and the key into the boxes above, press Test, then Save.
